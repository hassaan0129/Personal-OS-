# Git and GitHub workflow

- Start with `git status`, current branch, remotes, and recent history.
- Preserve uncommitted user work.
- Use focused branches: `feat/`, `fix/`, `chore/`, or `docs/`.
- Keep commits small, coherent, and imperative; never include secrets or generated noise.
- Review staged diff before committing.
- Do not amend shared history, force-push, push, merge, tag, release, or publish without explicit permission.
- For PR preparation, include summary, rationale, testing evidence, screenshots when relevant, migrations, risks, and rollback notes.
- Resolve conflicts semantically; never choose “ours” or “theirs” blindly.
